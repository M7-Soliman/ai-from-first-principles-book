BuildThe project

Ten to fifteen hours, and the centrepiece of the book so far. You build an automatic differentiation engine from nothing, then a neural network library on top of it, then train something real with it.

P.1 What you are building

tinygrad: a working autograd engine and the network library it supports.

The rule: no framework, no autograd, at any stage. NumPy for array arithmetic only. Everything else is yours, and by the end you will have rebuilt the core of PyTorch in a few hundred lines.

P.2 Stage 1: the scalar engine

Start with one value at a time. It is unbearably slow and it is the clearest possible version of the idea.

PieceNotes
ValueHolds data, grad, parents, and a local _backward.
+ - * / **Each records how to send a gradient to its parents.
relu, tanh, exp, logSame pattern, one local derivative each.
backward()Topological sort, then reverse walk. Accumulate with +=.

Deliverable: a gradient check against numerical differentiation on ten randomly generated expressions, including at least one that reuses a value, since that is exactly where accumulation bugs hide.

P.3 Stage 2: the network library

  • Neuron, Layer, MLP: built from Value.
  • parameters(): returns every trainable value, so the optimiser can find them.
  • Losses: squared error and cross-entropy, the second from logits.
  • An SGD optimiser with momentum: reuse Part III's.
  • zero_grad(), and a comment explaining why it is necessary.

Deliverable: train it on XOR and reach near-zero loss. Then train it on a spiral or two-moons dataset and plot the decision boundary.

P.4 Stage 3: make it fast

Rewrite the engine to operate on arrays rather than scalars. The structure is identical; only the local derivatives change from numbers to matrix expressions.

  • Tensor wrapping a NumPy array, with the same graph machinery.
  • Matrix multiply, with the backward pass you derived in §14.
  • Broadcasting, and its backward pass, which must sum over broadcast axes. This is the step people get wrong.
  • Softmax and log-softmax, fused and stable (Part III §4).

Deliverable: identical gradients to Stage 1 on the same problems, and a measured speedup. Report the factor.

P.5 Stage 4: train something real

  1. Load a real classification dataset: handwritten digits is the traditional choice.
  2. Train a two-hidden-layer network on it with your own library.
  3. Apply Part VI's discipline: train/validation/test, and Part V's intervals on the final number.
  4. Reproduce §20's diagnostic sequence, including deliberately breaking the model and confirming the overfit-ten-examples test catches it.

P.6 Stage 5: reproduce the part

Use your library as an instrument. One figure and caption each:

  1. Vanishing gradients. 25 layers, sigmoid versus ReLU, gradient by layer.
  2. Initialisation. Activation scale by depth at three scales.
  3. Cross-entropy versus squared error from a badly wrong start.
  4. Dead ReLUs against learning rate.
  5. Residual connections restoring gradient flow in the sigmoid network.

P.7 Stretch

  • Batch normalisation, including the backward pass, the hardest derivation here.
  • Gradient checkpointing, with peak memory measured.
  • Adam on your own engine, reusing Part III's implementation.
  • A convolution layer and its backward pass, which is the first section of the part that follows.

P.8 Done when

  • Gradient checks pass on expressions that reuse values.
  • XOR trains to near-zero loss from several random seeds.
  • The array engine gives identical gradients to the scalar one.
  • You have measured and reported the vectorisation speedup.
  • A real dataset trains, with an interval on the reported accuracy.
  • All five reproduction figures exist.
  • Your README names something the framework does that now seems obvious.
Why this project

This is the project the whole book has been building toward. Every earlier one supplied a piece: Part 0's gradient checker verifies it, Part I's matrix operations run inside it, Part II's cross-entropy is its loss, Part III's optimisers drive it, Part V's intervals evaluate it, Part VI's methodology governs the experiment.

After it, no framework is a black box. You will know why gradients accumulate, why the graph is retained, what detaching does, why in-place operations are dangerous, and what a custom backward has to provide. Those stop being rules to remember and become consequences of a design you built.

The one thing to carry forward

A network is a composed function, and backpropagation is the chain rule with bookkeeping.

There is no additional principle. Convolution, recurrence and attention change what the composed functions are; they do not change how the gradient is computed, what the loss means, or how the optimiser works.

That is why this part is the last one that introduces genuinely new machinery. Everything after it is architecture, which is a much smaller thing than it looks from outside.
