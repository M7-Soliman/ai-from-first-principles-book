Part BDetection

Twenty years of architectures for one problem, and the lineage is easier to follow as a sequence of answers to two questions: where do candidate objects come from, and what stops the background from swamping the loss.

§9 The two-stage idea

Propose, then classify

A first stage proposes a few hundred regions that might contain something; a second stage classifies each and refines its box. The proposals started as a hand-designed segmentation algorithm and became a small network sharing the backbone's features, which is the change that made the family fast enough to use.

The operation that makes it work is pooling a fixed-size feature from a variable-size region. Doing that by rounding to feature-map cells introduces a misalignment of up to half a cell, which is invisible for classification and matters for a mask; interpolating instead of rounding is the whole of the fix, and it is worth knowing because the same rounding appears wherever a continuous coordinate meets a discrete grid.

§10 The one-stage idea

Predict everywhere, all at once

Skip the proposal stage: predict a class and a box offset at every position of a feature map, in one pass. Faster and simpler, and it makes §7's imbalance far worse, because now every position contributes to the loss instead of a few hundred selected ones.

The accuracy gap between the families closed once the loss dealt with that imbalance, which is §14; so the historical two-stage-versus-one-stage argument turned out to be an argument about the loss rather than about the architecture.

§11 Anchors, and what replaced them

Go and read

Carion et al. (2020), End-to-end object detection with transformers. Detection as set prediction, with a matching loss and no suppression step. The strongest argument in it is the one about removing a non-differentiable, untuned post-process from the middle of a system.

Three ways to say where an object might be

Anchors. A fixed set of reference boxes at every position, in several scales and aspect ratios; the network predicts an offset from the nearest one. Effective, and it introduces hyperparameters (how many, what shapes, what overlap counts as a match) that are tuned per dataset and transfer badly.

Anchor-free. Predict the object's centre and its extent directly. Fewer hyperparameters, and the assignment of which position is responsible for which object becomes the design problem instead.

Set prediction. Emit a fixed number of queries and match them to ground truth by solving an assignment problem, so the loss is permutation-invariant by construction. This removes §12's suppression step entirely, which is the strongest argument for it, and it trains slowly because the assignment changes between epochs.

§12 Non-maximum suppression

The step that is not part of the model

A dense predictor fires several times on one object. Suppression sorts by confidence and deletes any lower-scoring box overlapping a kept one by more than a threshold.

It is greedy, it is not differentiable, it is usually not tuned, and it decides the output. It also cannot distinguish a duplicate from two genuinely overlapping objects, because the only evidence it uses is overlap.

§14 What the loss does about it

Go and read

Lin et al. (2017), Focal loss for dense object detection. The paper that closed the one-stage accuracy gap, and it is worth reading for the diagnosis rather than the fix: §3 shows the problem was the summed loss of easy negatives, not the hard ones, which is not what the name suggests.

Four responses, in the order they were tried

Sample. Use a fixed ratio of negatives to positives per image. Simple, and it throws away most of the data.

Mine the hard ones. Keep the negatives with the highest loss. Better, and it is a discrete selection inside a gradient method, with the instability that implies.

Down-weight the easy ones. Multiply each example's loss by a factor that shrinks as the prediction becomes confident and correct, the focal loss. This is the change that closed the one-stage accuracy gap, and it works because the problem was never that negatives were hard but that there were so many easy ones that their sum dominated.

Remove the duplicates from the problem. Set prediction assigns one prediction per object, so there is no imbalance to fix. Different family, same target.

Why the losses for the two heads differ

Classification uses cross-entropy. Box regression cannot: a squared error on coordinates weights a large box's error more than a small one's for the same relative accuracy, and it optimises something the metric does not use.

Optimising IoU directly is closer to the metric and has zero gradient when the boxes do not overlap, which is where a detector starts. The generalised and distance variants add a term that keeps pulling in that case: the same problem, and the same shape of fix, as Part XXVIII §41's transport distance replacing a divergence that is infinite on disjoint supports.

§15 Scale, and the pyramid

Go and read

Lin et al. (2017), Feature pyramid networks for object detection. Read beside Figure 4. The architecture is simple and the argument for it is arithmetic: small objects are not represented at the depth where the semantics live.

The feature pyramid

The fix is to detect from several depths at once, and the difficulty is that shallow layers have the resolution and not the semantics. A pyramid adds a top-down path carrying deep features back to shallow ones, so every level has both.

Assigning which level handles which object size is then a design decision, and it is the place small-object performance is usually lost. Note also that this is Part XXVII §5 in another costume: the downsampling that loses small objects is the same downsampling that breaks shift-consistency, and both are cured by paying attention to what a stride does.
