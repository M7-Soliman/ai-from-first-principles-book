BuildThe project

Eight to twelve hours, and the largest project so far. You implement every algorithm in this part from its definition, then run a fair contest between them and find out where each one breaks.

P.1 What you are building

tinylearn: a small machine learning library, then a bake-off that uses it honestly.

The rule: NumPy only. No sklearn, no frameworks. You have already written the linear algebra, the optimisers and the statistics in earlier projects, so reuse them.

P.2 Stage 1: a common interface

Give every model the same three methods, so the harness can treat them interchangeably:

class Model:
    def fit(self, X, y):    ...   # learn parameters
    def predict(self, X):   ...   # hard predictions
    def predict_proba(self, X): ... # where meaningful

Implement: LinearRegression (with a ridge option), LogisticRegression, KNN, DecisionTree, LinearSVM, KMeans, PCA.

Deliverable: every model passes a gradient check where applicable, and every fitted model reproduces a hand-checkable answer on a tiny dataset you can verify by hand.

P.3 Stage 2: the evaluation harness

  • train_val_test_split: with an option to split on time rather than at random.
  • k_fold and nested_cv.
  • learning_curve(model, X, y): error against training set size.
  • capacity_curve(model_family, X, y): error against a capacity knob.
  • Reuse Part V's bootstrap_ci and paired_bootstrap.

Deliverable: a harness that, given a model and a dataset, returns a metric with an interval. Never a bare number.

Watch for this in Stage 2

Any preprocessing that learns from data (standardisation, imputation, feature selection) must be fitted inside each fold, on the training portion only. Fitting it once on the whole dataset leaks validation information into training and inflates every score you produce. This is drill C16, and it is the most common bug in the stage.

P.4 Stage 3: the bake-off

Assemble four datasets with deliberately different structure:

  1. Linearly separable: where the simplest model should win.
  2. Concentric rings: where linear models must fail and kernels or kNN should not.
  3. Axis-aligned blocks: where a tree should dominate.
  4. High-dimensional with low intrinsic dimension: data on a manifold in 200-D.

Run every model on every dataset with equal tuning budget. Report a table of metrics with intervals.

Deliverable: the table, plus a paragraph per dataset explaining which assumption made the winner win. That explanation is the entire point: a bake-off without it is a leaderboard, and Section 7 says leaderboards without assumptions are meaningless.

P.5 Stage 4: find the walls

  1. The curse. Fix the sample size and grow the dimension. Plot kNN accuracy against $d$. Find where it degrades to chance.
  2. Intrinsic dimension rescues it. Repeat with data on a low-dimensional manifold embedded in the same high dimension. Show kNN survives.
  3. Kernels do not scale. Time kernel fitting against $n$. Confirm the quadratic growth, and estimate the $n$ at which it becomes impractical on your machine.
  4. SGD does. Time logistic regression by SGD against $n$. Confirm it is linear.

These four experiments are the empirical case for the rest of the book, established with your own code.

P.6 Stretch

  • Random forest: bag your trees and measure the variance reduction.
  • Gradient boosting: fit trees to residuals in sequence, and compare.
  • Kernel k-means: apply the trick to clustering and solve the concentric rings.
  • A real dataset end to end, with Part V's reporting checklist applied in full.

P.7 Done when

  • All seven models share an interface and pass their checks.
  • Preprocessing is fitted inside folds, and you have measured the leak it would cause.
  • Every reported number carries an interval.
  • Each dataset's winner is explained by an assumption, not by a score.
  • You have located the dimension at which kNN fails, and shown a manifold rescues it.
  • You have measured kernel methods going quadratic and SGD staying linear.
  • Your README names a model you expected to win that did not.
Why this project

Implementing seven algorithms teaches you that they are small (most are fifteen to forty lines) and that the difficulty was never the code. It is in knowing which assumptions each one makes and whether your problem satisfies them.

Stage 4 matters most. Once you have personally watched nearest neighbours degrade to chance as dimension grows, and then watched it recover when the data lies on a manifold, the argument for representation learning stops being something you were told and becomes something you measured.

The one thing to carry forward

Every model assumes something. The question is whether your problem agrees.

Linear models assume additivity. Trees assume axis-aligned splits. Nearest neighbours assumes smoothness. Convolution will assume locality; recurrence will assume temporal structure; attention will assume that relevance can be computed pairwise.

No assumption is universally right, as Section 7 forbids it. The skill is not collecting algorithms; it is reading a problem well enough to know which assumption fits, and recognising the failure when it does not.

What the foundations have established

Five parts and roughly three hundred pages ago this book started with arithmetic. What has been built:

  • The mathematics of change, and the chain rule that makes learning possible at all.
  • The algebra of the objects computation acts on.
  • A language for uncertainty, and the loss functions that fall out of it.
  • The numerical reality of doing any of it on a machine.
  • The statistics required to know whether it worked.
  • And now: what learning is, when it generalises, and precisely where the classical methods stop.

Everything from here is one model family: compositions of simple functions, with the features learned rather than chosen. The framework does not change again. Only column two of §20's table does.
