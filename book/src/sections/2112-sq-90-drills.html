PracticeDrills

Forty-five problems. Several ask you to reproduce a claim this part shows does not reproduce as usually stated: those are the valuable ones, because finding out which variable a famous comparison was actually varying is a skill that transfers.

Tier 0 Estimate first

EstimateE1 · Parameters in an LSTM

An LSTM with input size 512 and hidden size 512. Write down its parameter count before deriving it.

Answer. 2,099,200: four gates, each with an input matrix, a recurrent matrix and a bias. The factor of four is the thing to remember: an LSTM cell is four times a plain recurrent cell, which is most of why the comparisons against it in Part XI §21 have to be made at matched parameters rather than matched hidden size. Score yourself: within a factor of two is a pass, and an order of magnitude out is worth understanding before you go on.

Tier 1 Warm-up

WarmW1 · Why not pad

Give two objections to padding every sequence to a maximum length and using a dense layer.

Answer. You cap the model at that length and pay for the maximum on every example. And each position gets its own parameters, so nothing learned about position 3 transfers to position 40, Part X §1's objection, one axis over.
WarmW2 · Unfolding

What two things does unfolding buy?

Answer. A fixed input size regardless of sequence length, because the model is a transition rather than a function of history. And one transition function shared across steps, so it can be estimated from far less data and generalises to lengths never seen in training.
WarmW3 · Three matrices

Name $U$, $V$ and $W$ by what they connect, and say which one causes all the trouble.

Answer. $U$ input-to-hidden, $W$ hidden-to-hidden, $V$ hidden-to-output. $W$: it is the one applied repeatedly, so it is the one raised to a power.
WarmW4 · Two costs of BPTT

State them, and say which one more hardware fixes.

Answer. $O(\tau)$ time, inherently sequential; $O(\tau)$ memory for stored states. Hardware fixes neither: the memory can be traded against recomputation, but the sequential dependency is what recurrence means.
WarmW5 · Bias, not noise

Why is a truncated gradient categorically different from a minibatch gradient?

Answer. A minibatch gradient is unbiased: noise around the truth, so averaging recovers it. Truncation deletes every path longer than $k$. Averaging does not bring them back, so the model cannot learn a dependency longer than its window at all.
WarmW6 · The counting

A joint table over a length-$\tau$ sequence with vocabulary $k$ needs how many numbers, and an RNN how many?

Answer. $O(k^\tau)$ against $O(1)$ in $\tau$. At $k=10$, $\tau=20$ that is $10^{20}$ against about four thousand. The table passes the atom count of the observable universe at a sequence of 80 tokens.
WarmW7 · Stationarity

State the assumption parameter sharing across time makes, and give a case where it is false.

Answer. The conditional distribution of step $t+1$ given step $t$ does not depend on $t$. False for a regime change in a financial series, a scene cut, or any diurnal cycle, and the model has no way to say so, because it has one $f$.
WarmW8 · Leaky memory

A leaky unit uses $\alpha = 0.98$. Roughly how far back does it remember?

Answer. $1/(1-\alpha) = 50$ steps. Same formula as momentum's window (Part III §15), RMSProp's gradient accumulator (Part III §16), batch normalisation's running statistics (Part IX §23), Polyak averaging (Part IX §25), and now leaky units (one geometric series, five uses).
WarmW9 · One line

Write the leaky-unit update and the LSTM cell update side by side. What changed?

Answer. $\mu \leftarrow \alpha\mu + (1-\alpha)v$ against $s \leftarrow f s + g v$. The fixed $\alpha$ became a quantity the network computes at every step, and the two coefficients became independent. That is the entire idea.
WarmW10 · The bottleneck

Why can widening the context vector not fix the encoder–decoder problem?

Answer. Because the encoder must decide what to keep before knowing which output it will be asked for first. No fixed summary computed in ignorance of the question is right for every question, and Figure 9 measures the sixteen-fold widening recovering 0.328 to 0.444.

Tier 2 Core

CoreC1 · Write the forward pass

Implement §4's RNN by hand ($\tanh$ state, softmax output, loss summed over steps) and check it against a library implementation.

Answer. Agreement to float32 rounding. Watch the shapes: the library wants $(T, N, C)$ unless you ask otherwise, and the state has a leading layer axis.
CoreC2 · BPTT by hand

Write the backward pass yourself, unrolled, and gradient-check every one of $U$, $V$, $W$ and the biases.

Answer. The gradient with respect to $W$ is a sum over all time steps, because $W$ is used at every one: that is where the errors live. Forgetting the accumulation gives a gradient that looks plausible and trains to something worse.
CoreC3 · Measure the truncation bias

Compute the exact gradient and the gradient truncated at $k$, for a range of $k$. Report the relative error and the cosine.

Answer. The direction recovers far faster than the magnitude: cosine 0.85 at $k=1$, 0.995 at $k=5$, 1.0000 by $k=20$, while the relative error is still 0.11 at $k=5$. That gap is why truncation works at all.
CoreC4 · The Jacobian product

Build a linear recurrence with spectral radius 0.9, 1.0 and 1.1 and plot $\|\partial\mathbf{h}^{(t)}/\partial\mathbf{h}^{(0)}\|$. Then repeat with $\tanh$ and measure by autograd.

Answer. The linear case is exactly $\rho^t$. The $\tanh$ case still vanishes and can still overflow float32 at gain 2, because $\tanh$ bounds the forward state and nothing bounds the product of Jacobians. Confusing those two is the standard misreading.
CoreC5 · The cliff grows with the data

For a scalar recurrence, plot the loss against $w$ for several $T$, and $|dL/dw|$ at a fixed $w$ against $T$.

Answer. $2.7\times10^{2}$ at $T=10$ and $7.2\times10^{7}$ at $T=40$. Note what this means: the model did not change, the input length did. A learning rate tuned on short sequences is not safe on long ones.
CoreC6 · Clip two ways

Implement norm clipping and element-wise clipping and measure the angle each introduces between the clipped and unclipped gradient.

Answer. Norm clipping: exactly zero; it rescales. Element-wise: a real rotation, growing with how uneven the gradient is. And note both address explosion only; neither touches vanishing.
CoreC7 · Reproduce the failure, and fail to

Train a vanilla RNN on a task where the answer is the first input and the rest is noise, for $T$ from 5 to 80. Do it with plain SGD and no clipping, then with Adam and clipping.

Answer. The failure appears under plain SGD and largely disappears under Adam with clipping. The textbook claim is partly a statement about the optimiser of 1994. Report both arms; reporting one is how the confusion started.
CoreC8 · The forget-gate bias

Train the same LSTM at forget-gate bias 0, 1 and 2, and at the library default. Sweep $T$.

Answer. At $T=40$ the default reaches 0.769 and a bias of 1 reaches 0.997. A bias of 0 puts the gate at $\sigma(0)=0.5$, so an untrained LSTM halves its cell every step, the exact decay the cell exists to prevent, and it must learn to open the gate through a gradient the closed gate is destroying.
CoreC9 · Read the gates

Train an LSTM to solve a long-lag task, then run it and record the mean input, forget and output gate activations, and the cell magnitude, over time.

Answer. The forget gate settles near 0.9: the network discovers the time constant the task needs. The cell magnitude grows rather than holding, because the input gate keeps admitting noise; what makes the task solvable is that the signal survives alongside, not that the noise is excluded.
CoreC10 · Gate order

Determine empirically which quarter of a library LSTM's bias vector is the forget gate, without reading the documentation.

Answer. Zero all biases, set one quarter to 1, and see which gate moves to $\sigma(1) = 0.731$. The order is input, forget, cell, output, and there are two bias vectors that are summed, so setting both gives $\sigma(2) = 0.881$.
CoreC11 · Teacher forcing is maximum likelihood

Factorise $\log p(y^{(1)}, y^{(2)} \mid \mathbf{x})$ and read off what the model should be conditioned on at $t=2$.

Answer. The chain rule gives $\log p(y^{(2)} \mid y^{(1)}, \mathbf{x}) + \log p(y^{(1)} \mid \mathbf{x})$. The conditioning variable is the observed $y^{(1)}$, not the predicted one, so teacher forcing is what the likelihood asks for, and feeding back the model's own output optimises something else.
CoreC12 · Exposure bias, measured

Train with teacher forcing, then generate free-running, and measure how far the generated distribution drifts from the training distribution as a function of steps generated.

Answer. It compounds: one slightly wrong token yields a prefix off the training manifold, which yields a worse next token. The model has an opinion about correct prefixes and no opinion about its own mistakes, because it never saw one during training.
CoreC13 · The bottleneck

Build a seq2seq model with an explicit context width and sweep both the input length and the width.

Answer. Accuracy falls steeply with length and rises only gently with width: 0.328 to 0.444 for a sixteen-fold widening at length 24. Use a task where the output depends on every input token, or the encoder can discard most of it legitimately and you will measure nothing.
CoreC14 · A reservoir

Fix the recurrent weights at random with spectral radius near 1, train only a linear readout, and compare against a fully trained RNN of the same size.

Answer. Closer than expected, and the readout is a convex problem solved in one shot. Sweep the spectral radius: too small and the reservoir forgets before the readout can use anything, too large and it is chaotic. Any claim about learned temporal representations should be compared against this baseline and usually is not.

Tier 3 Stretch

StretchS1 · Which variable was the famous comparison varying

Run the full grid: {vanilla, LSTM, GRU} × {SGD, Adam} × {clip, no clip} × {default bias, bias 1} on the same task and lengths. Attribute the variance.

Answer. The architecture is not the largest term. That is the point, and it is Part X §26's ConvNeXt lesson arriving in a different literature. Report the full grid; a single number comparing two architectures across four changed variables is not evidence about architectures.
StretchS2 · Where gating genuinely wins

Design a task that requires selective memory (remember this, ignore that, now overwrite) rather than mere survival. Compare vanilla against gated.

Answer. Here the gap is real and large, which is the honest complement to §14. A vanilla RNN can be coaxed into holding a signal; it cannot easily learn to clear its state on a cue, because it has no mechanism whose job that is.
StretchS3 · Truncation you can see

Construct a task with a dependency at exactly 200 steps. Train with truncation at 50, 100 and 400. Plot the learning curves.

Answer. Truncation at 50 and 100 never learn it: not slowly, never, because the gradient for that dependency is identically absent. The loss curve looks like a model that has converged, which is why this failure is so hard to diagnose from the curve alone.
StretchS4 · Skip connections through time

Add connections spanning $d$ steps and measure the gradient norm reaching step 0 for $d \in \{1, 2, 5, 10\}$.

Answer. Decay becomes exponential in $\tau/d$ rather than $\tau$, a genuine improvement to vanishing that does nothing for explosion, since the short connections are still present. And $d$ fixes the reachable time scale in advance, which is what leaky units improve on.
StretchS5 · Packing

Train on variable-length sequences with and without packing, at several length variances. Measure the damage.

Answer. Without packing the recurrence consumes the padding and the final state is the state after reading zeros, so the damage grows with how variable your lengths are. It never raises, it never warns, and the model is merely worse.
StretchS6 · Bidirectional, and what it costs

Compare unidirectional and bidirectional models on a labelling task. Then measure the latency of each in a streaming setting.

Answer. Bidirectional wins the benchmark and is unusable for streaming, because it must see the whole sequence before emitting anything. The benchmark does not measure the constraint that decides the application, a category of error Part XIV returns to.

Movement G What came after

EstimateE2 · When is quadratic actually expensive

A model with $d=4096$. Before computing: at what sequence length does attention's arithmetic per layer exceed a linear-state layer's? Then say what that means for a 8,192-token context.

Answer. Attention is $4L^2d+6Ld^2$, linear is $10Ld^2$. The projection terms cancel ($4L^2d = 4Ld^2$), so the crossover is $L=d$ = 4,096. At 8,192 tokens attention costs about twice as much; at 2,048 it is cheaper. Comparing the quadratic term alone against the full linear cost gives 2.5d, which is the mistake that is easy to make in your head. Score yourself: within a factor of two is a pass.
Warm-upW12 · Where the quadratic cost actually hurts

If attention is often cheaper in training arithmetic, why does anyone want a recurrent layer?

Answer. Generation. Attention's cost for the next token grows with the context already produced, and so does the KV cache; a fixed state makes both constant. The case for recurrence is an inference case, and quoting "linear versus quadratic" without saying which workload hides that.
Warm-upW13 · Why the softmax blocks factorisation

What exactly stops attention being computed as a running sum?

Answer. $\exp(q\cdot k)$ does not factor into a function of $q$ times a function of $k$, so every pair must be formed. Replace it with $\phi(q)\cdot\phi(k)$ and the sum over keys can be accumulated once, which is the same thing as a matrix-valued recurrence.
Warm-upW14 · Why linearity is the price

Why did the recurrence have to become linear to be parallelised?

Answer. Only an associative composition can be evaluated by a scan, and $h_t=a_th_{t-1}+b_t$ composes associatively while a gated nonlinear recurrence does not. §16's gates bought gradient behaviour with nonlinearity; giving that up is what buys the log-depth evaluation, and gating then has to be recovered as an input-dependent decay instead.
CoreC21 · Count the crossover yourself

Write out the FLOP counts for attention and a linear-state layer and solve for the crossover length. Check it against Figure 10 at two model dimensions.

Answer. $4L^2d+6Ld^2 = 10Ld^2$ reduces to $4L^2d = 4Ld^2$, so $L=d$: the projections cancel entirely. Drop them from only one side and you get 2.5d. Counting arithmetic rather than timing it is deliberate: a FLOP count is a property of the algorithm and transfers, and a wall-clock number would belong to one machine, the argument Part XXXII makes at length.
CoreC22 · Linear attention as a recurrence

Implement linear attention twice (once as a quadratic-form attention matrix, once as a running matrix state) and assert the outputs agree to floating-point tolerance.

Answer. They must agree exactly, because reassociating a sum is an identity rather than an approximation. If they differ, the usual cause is the normaliser: it is a separate running sum $\sum_j\phi(k_j)$ and must be accumulated alongside the state. Writing both forms is what makes "linear attention is an RNN" stop being a slogan.
CoreC23 · Measure how sharply a layer can point

Reproduce Figure 11: set the query equal to a target key and measure the largest achievable weight, for softmax and for a positive feature map, across lengths. Then sweep the dimension.

Answer. Softmax stays near one; linear attention stays near $1/L$, and the gap widens with length. The dimension sweep is the surprise: it does nothing for linear attention, because a positive feature map makes every score a sum of positive terms with a large common component. Use $O(1)$ entries for keys and queries: scaling them down drives $\phi(k)$ toward a constant and every key scores the same, which produces the right-looking flat line for the wrong reason.
CoreC24 · Write an associative scan

Implement $h_t=a_th_{t-1}+b_t$ sequentially and by a scan. Assert they agree, then count depth and work for each.

Answer. The composition is $(a_1,b_1)\circ(a_2,b_2)=(a_1a_2,\;a_2b_1+b_2)$. Depth falls from $L$ to $\log_2 L$; work rises. Note which scan you wrote: Hillis–Steele is $O(L\log L)$ work and Blelloch is $O(L)$, both are called "parallel scan", and the difference is a factor of $\log L$ in arithmetic.
CoreC25 · Discretise a state space model

Take $h'=Ah+Bx$ and discretise it with step $\Delta$. Show the unrolled system is a convolution and write down its kernel.

Answer. $\bar{A}=\exp(\Delta A)$, and the kernel is $(C\bar{B},\,C\bar{A}\bar{B},\,C\bar{A}^2\bar{B},\dots)$, so training can use an FFT. The eigenvalues of $A$ are the timescales: §12's vanishing gradient restated as a choice about where to put them.
CoreC26 · Measure a state's capacity

Store $L$ key–value pairs in an outer-product memory and measure recall as $L$ grows, for several state sizes. Find the length at which recall halves.

Answer. It is proportional to the state size: doubling the state doubles the usable length, with no fitted constant. No training is involved, which is the point: the limit is a property of the representation, not of an optimiser. Bracket the transition with your length grid, or the width you report is a property of the grid.
CoreC27 · A fixed decay's half-life

Derive the half-life of $h_t=\lambda h_{t-1}$ and check it numerically for several $\lambda$.

Answer. Exactly, the $h$ solving $\lambda^h=1/2$, which is $-\ln 2/\ln\lambda$. The familiar $\ln 2/(1-\lambda)$ is its limit as $\lambda\to1$ and is 5% high already at $\lambda=0.9$. Either way the effective memory scales as $1/(1-\lambda)$ and the half-life is $\ln 2$ of it: about seven steps at 0.9, thirty-five at 0.98.
StretchS7 · Selective copying

Build a sequence of noise containing a few marked tokens, and recover the last marked value. Sweep the fixed decay, then implement an input-dependent gate, then degrade the gate and find where it stops winning.

Answer. No fixed decay does well: it must average in everything it sees. A perfect gate is exact. Degraded, it still wins until it is wrong on a substantial fraction of tokens. The state is one number in both arms, so this measures the mechanism rather than the capacity. Beware of designing a task no scalar state can solve at all: asking one number to hold a distant landmark and the most recent token measures an impossibility, not a mechanism.
StretchS8 · Price a hybrid

For a stack of $N$ layers of which $k$ are full attention, write the KV cache size and the per-token generation cost. Find the $k$ that keeps the cache under a budget, then test what it costs on a retrieval task.

Answer. Cache and per-token cost both scale with $k$ rather than $N$, so a few attention layers in a deep stack are cheap. The point of the second half is that the accounting is easy and the capability question is not: measure retrieval directly, because an averaged loss will not show you what Figure 13 shows.
StretchS9 · Make the comparison honest

Compare a recurrent-state layer against attention on a long-context task, holding parameters, training tokens and wall-clock equal in turn. Report how the ranking changes.

Answer. It changes, which is the exercise. Equal parameters favours the mechanism with more state per parameter; equal wall-clock favours the cheaper one at your length; and a retrieval metric and an average loss can rank the two differently on the same run. Say which you held fixed: most published comparisons of these families differ mainly in that choice.
