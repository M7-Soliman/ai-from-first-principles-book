PracticeDrills

Fifty-three problems. Most of this part is about establishing what a representation holds, so most of these build an instrument and then find out what it cannot see.

Tier 0 Estimate first

EstimateE1 · The cost of an index

One million embeddings of dimension 768 at float32. Write down the memory, and the multiply–adds for one exact nearest-neighbour query.

Answer. 3.1 GB and 7.7×108 multiply–adds per query. Which says why approximate search exists: exact search is a matrix–vector product against the whole corpus, and at a thousand queries a second that is a teraflop of work for something users expect to be instant. Score yourself: within a factor of two is a pass, and an order of magnitude out is worth understanding before you go on.

Tier 1 Warm-up

WarmW1 · Why copying is not enough

An autoencoder reaches zero reconstruction error. What have you learned?

Answer. Nothing. It has learned the identity function on the training set. An autoencoder is useful only when it is prevented from copying (by a bottleneck, a penalty, or corrupted input) so that it must choose what to keep.
WarmW2 · The index-code argument

Show that a one-dimensional code can give perfect reconstruction, and say what it proves.

Answer. Let the encoder map example $i$ to the number $i$ and the decoder be a lookup table. Perfect reconstruction, useless representation. It proves that a narrow bottleneck is not sufficient for a useful code: only a bottleneck the encoder is too weak to circumvent is.
WarmW3 · Distributed against symbolic

Why are cat and dog as far apart as cat and Tuesday under one-hot encoding, and what changes with a distributed code?

Answer. Every pair of distinct one-hot vectors is at squared distance 2, so the encoding carries no similarity information at all. A distributed code lets concepts share entries, so what is learned about one transfers to the other. That sharing is the mechanism of generalisation, not a side benefit.
WarmW4 · The exponent

"A distributed representation with $n$ features is exponentially more expressive." State what is wrong with this and give the correct count.

Answer. The number of regions $n$ linear-threshold features carve in $\mathbb{R}^d$ is $\sum_{j=0}^{d}\binom{n}{j} = O(n^d)$: polynomial in $n$, exponential in $d$. The $2^n$ figure counts code configurations, most of which are never realised once $n > d$. The advantage is still enormous: 40 features in 10 dimensions give over a billion regions against 40.
WarmW5 · The two forces

Name them, and say why neither alone is any use.

Answer. Reconstruct the training data, and satisfy the constraint. Alone, the first gives the identity function and the second gives a constant. Together they force the representation to keep exactly the variation needed to reconstruct real data.
WarmW6 · Score

Define the score of a density and say why it can be learned when the density cannot.

Answer. $\nabla_{\mathbf{x}} \log p(\mathbf{x})$. The gradient of a log annihilates any constant factor, so the intractable normalising constant $Z$ never appears.
WarmW7 · What a denoiser learns

Give the identity relating a denoising autoencoder to the score, and name the distribution it actually applies to.

Answer. $(g(f(\mathbf{x})) - \mathbf{x})/\sigma^2 \approx \nabla_{\mathbf{x}} \log p_\sigma(\mathbf{x})$, where $p_\sigma$ is the data density convolved with the corruption noise, not the data density. At fixed $\sigma$ the estimator is inconsistent; it recovers a blurred distribution.
WarmW8 · Collapse

What is the global optimum of "make two views of the same input agree", with no other term?

Answer. Map every input to the same vector. Agreement is perfect and the representation is empty. This is the minimum, not an accident, and something must push outward: negatives, or an asymmetry like a stop-gradient and predictor.
WarmW9 · What a t-SNE plot supports

Two clusters are drawn far apart and one is visibly tighter. What may you conclude?

Answer. Neither. Distances between well-separated clusters are close to arbitrary and relative cluster sizes are not preserved: the algorithm rescales each neighbourhood to a fixed perplexity by construction. You may conclude only that groups exist and roughly which points are near which.

Tier 2 Core

CoreC1 · Subspace, not axes

Train a linear autoencoder with a $k$-dimensional code and compare it to rank-$k$ PCA two ways: principal angles between the subspaces, and the cosine between each code direction and the matching principal component. Explain the difference.

Answer. Angles near zero, per-axis cosines scattered. For any invertible $R$, $(RW, VR^{-1})$ has identical loss, so the objective determines the code only up to a linear change of basis. PCA's axes come from an extra orthogonality-and-ordering requirement that reconstruction never makes.
CoreC2 · Denoising recovers the score

Take a Gaussian mixture whose score you can write in closed form. Train a denoiser with corruption $\sigma$. Compare $(r(\mathbf{x})-\mathbf{x})/\sigma^2$ to the analytic score, both with and without adding $\sigma^2$ to each component's variance. Report cosine and magnitude ratio separately.

Answer. Against the smoothed score, both near 1. Against the unsmoothed score the cosine is still high (direction is barely affected) and the magnitude is substantially too small, because blurring flattens the density. Reporting only cosine would hide the error entirely.
CoreC3 · Sweep the noise level

Repeat C2 for $\sigma \in \{0.05, 0.1, 0.2, 0.5, 1.0\}$. Plot the agreement with the unsmoothed score against $\sigma$. What is the tradeoff?

Answer. Large $\sigma$ gives a well-estimated score of a badly blurred density; small $\sigma$ gives the right target and almost no training signal far from the data, because corrupted points never land there. Neither end works alone, which is the argument for using many noise levels at once, Part XVI's opening.
CoreC4 · Tie the weights

Implement a contractive autoencoder without tied weights and show the penalty can be driven to zero without learning. Then tie them and show it cannot.

Answer. Untied, scale the encoder by $\epsilon$ and the decoder by $1/\epsilon$: reconstruction is unchanged and $\Omega \to 0$. Tying removes the degree of freedom. The same class of failure as C1: a symmetry of the objective that must be broken by construction.
CoreC5 · InfoNCE, stably

Implement it and verify at $\tau = 10^{-3}$ that a naive $\exp$ overflows and log-sum-exp does not. Confirm matched pairs give lower loss than shuffled ones.

Answer. Part III §4's trick, in the loss everyone uses. Subtract the row maximum before exponentiating.
CoreC6 · Alignment and uniformity

Implement both and report them for: a well-trained contrastive encoder, a collapsed one, and a random one. Which single number would have failed to distinguish them?

Answer. The collapsed encoder has excellent alignment and terrible uniformity; the random one the reverse. The loss alone conflates them, and reporting the pair explains results that the loss does not.
CoreC7 · Effective rank

Implement it and confirm: isotropic Gaussian data in $d$ dimensions returns approximately $d$; data on a line returns approximately 1, whatever the ambient dimension.

Answer. $\exp$ of the entropy of the normalised eigenspectrum. It is the cheapest useful instrument for watching a self-supervised run, and §20 is why.
CoreC8 · Do the two instruments agree

Train with positives only. Log effective rank and linear-probe accuracy every few hundred steps. Then repeat on a task made deliberately easy, where the property is linearly readable straight off the raw input. Compare when each instrument notices the collapse.

Answer. On the hard task they fall together. On the easy one the probe lags badly, still reporting near-perfect accuracy on a code of effective rank 1.04, because the tiny surviving directions are enough when the property was nearly free to begin with. So a probe is not a reliable collapse monitor and is not reliably a bad one either: it depends on the task and on the probe's own regularization. Log the rank, which depends on neither.
CoreC9 · The augmentation is the specification

Build data from two known factors. Train contrastively three times, varying which factor the two views may disagree on. Probe for both factors each time.

Answer. The varied factor is discarded to near chance and the other is retained. With neither varied, both are kept and the code stays high-rank. The augmentation set is the task definition, written as invariances.
CoreC10 · The control task

Assign every example identity a fixed random label. Train a linear probe and an MLP probe on the real task and on this control. Report accuracy and selectivity for both.

Answer. The MLP scores high on the control (it memorises the identity mapping) so its selectivity collapses toward zero and its accuracy on the real task establishes nothing. Selectivity, not accuracy, is the quantity that carries a claim.
CoreC11 · Hubness

Sample Gaussian points in $d \in \{2, 10, 100, 500\}$. Report the skew of $N_{10}$, the largest hub, and the fraction of points that are nobody's neighbour. Then correlate hub-ness with distance from the centroid.

Answer. Skew and hub size grow sharply; a large fraction become unreachable. The correlation with centrality is strong and is the mechanism: a point nearer the centre is nearer to everything, and that small advantage applies to every query.
CoreC12 · Fixing hubness

Take the $d=100$ case and apply, separately: centring, and the mutual-$k$NN graph. Measure the hub statistics again.

Answer. Both reduce it, for different reasons: centring removes the shared component that creates the advantage, mutual-$k$NN discards one-directional hub edges by construction. Note what mutual-$k$NN costs: some points end up with no neighbours at all.
CoreC13 · Anisotropy

Measure the mean cosine between random pairs of embeddings from any trained encoder. Then centre and measure again. Report both, and the effect on retrieval accuracy.

Answer. The raw value is typically far above zero; centring removes most of it. Retrieval usually improves or is unchanged, and the reason to measure first is that a compressed similarity distribution is a diagnosis, not a mystery.
CoreC14 · What t-SNE destroys

Construct clusters with known, deliberately different spreads and separations. Run t-SNE at three perplexities. Report the ratio of cluster spreads and of gaps, before and after.

Answer. Both ratios collapse toward 1 and the result changes with perplexity. This is the algorithm working as defined: its objective contains no term preserving either ratio.
CoreC15 · Superposition

Train the toy model: $n$ features, $m < n$ dimensions, output $\text{ReLU}(W^{\top}W\mathbf{h} + \mathbf{b})$, with importance decaying across features. Sweep the feature sparsity and count how many features are stored.

Answer. With dense features exactly $m$ are stored, orthogonally, and the rest are dropped. As sparsity rises the count climbs well past $m$: features share directions because they rarely co-occur, so the collision rarely costs anything.
CoreC16 · Interference

For the same runs, measure the mean absolute off-diagonal of the normalised Gram matrix. Relate it to the number of features stored.

Answer. Storing more than $m$ features forces non-zero interference: there are not enough orthogonal directions. Superposition is a bet that the crosstalk is rarely paid, and the interference number is the size of the bet.
CoreC17 · Sparse coding by ISTA

Implement soft-thresholding and ISTA. Recover a known sparse code from a known dictionary, and confirm that raising $\lambda$ monotonically reduces the number of non-zeros.

Answer. The step size $1/\|DD^{\top}\|_2$ is the largest one guaranteed to converge. Note that the encoder here is an optimisation, not a function, which is the difference between sparse coding and a sparse autoencoder, and the reason the latter is fast. Predictive sparse decomposition is the historical bridge: train a fast feed-forward encoder alongside the slow ISTA solve, penalised by the gap between the two, so inference becomes a function call once the encoder has learned to approximate the optimum. It is the amortised-vs- iterative distinction made into a training method.
CoreC18 · Dictionary recovery

Learn a dictionary from data generated by a known one. Match learned atoms to true atoms by absolute cosine. Why absolute, and why matching rather than comparing in order?

Answer. Atoms are identified only up to sign and permutation: flipping an atom's sign and its coefficients' signs changes nothing. The same degeneracy as C1, and the reason every comparison in this area is up to a group.
CoreC19 · Probe the layers

Take any pretrained network and probe every few layers for two properties: one the training task needed, one it did not. Plot accuracy against depth for both.

Answer. The task-relevant property rises toward the top. The irrelevant one usually peaks in the middle and falls, because later layers were rewarded for discarding it. This is why "use the penultimate layer" is bad default advice.
CoreC20 · Probe against fine-tune

At label budgets spanning three orders of magnitude, compare a frozen encoder with a linear probe against full fine-tuning. Evaluate both in-distribution and on a shifted test set.

Answer. Fine-tuning wins in-distribution with enough labels and can lose out-of-distribution, especially with few labels. Probing first and then unfreezing recovers most of the gap.

Tier 3 Stretch

StretchS1 · A denoiser at many noise levels

Train a single network conditioned on $\sigma$, on a schedule of noise levels. Verify it recovers the score at each. Then use it: start from noise and follow the field, annealing $\sigma$ downward. You have built a sampler.

Answer. This is diffusion, and it is a short step from C2. Part XVI derives it properly, including why the annealing schedule is the whole difficulty.
StretchS2 · Stop-gradient

Implement the no-negatives objective three ways: plain, with a predictor, and with a predictor and a stop-gradient on the target branch. Track effective rank for each.

Answer. Only the third avoids collapse. Removing either the predictor or the stop-gradient collapses it. The asymmetry is what prevents the trivial solution, and no term in the loss pushes anything apart.
StretchS3 · A sparse autoencoder on activations

Take a trained network. Collect activations from one layer. Train an overcomplete sparse autoencoder on them. Inspect the top-activating inputs for individual learned features and judge whether they are more interpretable than the raw neurons.

Answer. Usually yes, and the reason is C15: the raw neurons are in superposition, so each responds to several unrelated things. The sparse autoencoder is looking for the overcomplete basis the superposition was built from. Report the reconstruction error and the fraction of features that are dead; both are commonly omitted.
StretchS4 · Analogies, honestly

Reproduce $\text{king} - \text{man} + \text{woman}$ on public word vectors. Report accuracy with and without excluding the three query words from the candidate set, and break the result down by relation type.

Answer. Excluding the inputs raises the number substantially: without it the nearest vector is very often one of the inputs. And accuracy varies enormously by relation. The aggregate number is real and is doing more averaging than its fame suggests.
StretchS5 · Unidentifiability, constructed

Take two independent latent factors. Construct an invertible map to two different independent factors that induces the identical distribution over observations. Confirm no data-derived objective can distinguish them.

Answer. A rotation of independent Gaussians is the easy case, and the result holds far more generally. This is why unsupervised disentanglement is impossible without extra information, and why weak supervision, temporal structure or interventions are what restore identifiability.
StretchS6 · Retrieval, end to end

Build an index over at least $10^5$ embeddings. Measure recall@10 against exact search, then separately measure how good exact search itself is on your task. Diagnose which component is costing you.

Answer. The two losses are independent and are routinely conflated. If exact search is also poor, the index is innocent. Apply centring and re-measure both: §26 is why the encoder is guilty more often than teams expect.
StretchS7 · An augmentation that destroys your task

Pick a task where a standard augmentation removes the signal: colour for bird species, rotation for digits, cropping for counting. Pretrain with and without it and measure the damage.

Answer. Large and entirely predictable from §19. Worth doing once, because it converts "choose good augmentations" from advice into a measurement you know how to make.
StretchS8 · The modality gap

Train a two-tower contrastive model on paired data. Then measure the mean embedding of each modality and the distance between them. Are matched pairs closer to each other than to the other modality's centre?

Answer. The two modalities typically occupy separate cones with a substantial gap, despite the objective aligning matched pairs. Contrastive training aligns relative similarities, and nothing in it requires the two clouds to coincide, so cross-modal absolute distances are not comparable to within-modal ones.

Movement G Learning as compression

EstimateE2 · What a bit of rate buys

A Gaussian source, squared-error distortion. Before computing: how much does the distortion fall per extra bit per sample? Then estimate the total rate to reach a signal-to-noise ratio of 40 dB.

Answer. $R(D)=\frac12\log_2(\sigma^2/D)$, so each bit quarters the distortion: 6 dB per bit. Forty decibels needs about 6.7 bits per sample, plus the quarter-bit overhead any one-sample-at-a-time quantiser pays. Score yourself: within a factor of two is a pass.
WarmW10 · Whose property is $R(D)$

Is the rate–distortion function a property of the codec or of the source?

Answer. Of the source and the distortion measure. It is the boundary of what any codec could achieve, which is why every measured quantiser sits above it and why the interesting number is the gap rather than the rate.
WarmW11 · The two parts

What are the two terms of a two-part code, and why does their sum have an interior minimum?

Answer. Bits for the model and bits for the residuals under it. The first rises with complexity and the second falls, so the sum dips. Noise is incompressible, so paying parameters to encode it is a bad trade, which is why the minimum is near the true complexity.
WarmW12 · Two kinds of compression

Why are an autoencoder's code and a classifier's penultimate layer not interchangeable?

Answer. One compresses for reconstruction and keeps what is large; the other compresses for prediction and keeps what is relevant. A direction can carry most of the variance and none of the signal, and Figure 13 measures the two rules differing by nearly a factor of two at the same rate.
CoreC21 · Measure the gap to the bound

Quantise a Gaussian sample with a uniform quantiser at several step sizes, entropy-code the output, and plot the excess rate over $R(D)$.

Answer. It converges to $\frac12\log_2(\pi e/6)\approx0.2546$ bits. Charge the entropy of the output rather than $\log_2 k$: billing a fixed-rate code for its unequal cell probabilities measures the code rather than the quantiser, and the constant will not appear.
CoreC22 · Optimal under which constraint

Compare Lloyd–Max against a uniform quantiser, both entropy-coded, at matched rates.

Answer. Lloyd–Max is worse, about 0.14 bits, despite being optimal at a fixed number of levels. Density-adapted cells minimise distortion per level and cost entropy; uniform cells are the right answer once the output is entropy-coded. A method optimal under one accounting can lose under another, and which one you are paying is the first question.
CoreC23 · Quantise two dimensions at once

Implement a hexagonal lattice quantiser and measure its gap against the uniform scalar one.

Answer. About 0.022 bits better, against a theoretical 0.028. Do not round coordinates independently in a skewed basis: that finds the nearest point of a parallelogram tiling, whose second moment is worse than the hexagon's, and reports the gain with the wrong sign. Quantise to two rectangular sublattices and keep the closer.
CoreC24 · Select a model with no validation set

Fit polynomials of increasing degree, compute the two-part code length, and pick the minimum. Compare against held-out selection over many datasets.

Answer. The two agree on the mean curve and on a majority of individual datasets, 63% in Figure 12, and MDL finds the true degree about 80% of the time. Report the per-dataset agreement, not just the agreement of the averages: they are very different numbers and only one of them is a claim about your next dataset.
CoreC25 · The code you choose is a prior

Redo C24 with a cruder parameter code (a fixed number of bits per parameter) and see how the selected degree moves.

Answer. A more expensive parameter code biases selection toward simpler models. MDL is not parameter-free; it relocates the arbitrariness from a regularisation constant to a coding scheme, where at least it has an interpretation you can argue about.
CoreC26 · Trace a bottleneck frontier

On a small discrete joint distribution, iterate the information bottleneck at several values of $\beta$ and plot $I(Z;Y)$ against $I(X;Z)$.

Answer. A concave frontier that saturates at $I(X;Y)$. Construct the distribution so that the most probable structure and the predictive structure differ: otherwise every compression rule agrees and the figure shows nothing.
CoreC27 · The reconstruction-first control

Add the rule "keep the most probable symbols" at matched rates and plot it against the bottleneck.

Answer. It retains far less about the label, 0.746 bits against 1.373 in Figure 13. This control is what turns "the bottleneck finds relevant structure" from an assertion into a measurement, and it is cheap.
CoreC28 · Compression against generalisation

For two model families, plot test error against description length. Then repeat using residual bits only.

Answer. With the full two-part code the two track each other tightly, within families and across them. On residual bits alone the criterion picks a more complex model with worse test error, degree 7 against degree 3 in Figure 14. The model's own cost is what makes compression a selection criterion rather than a fitting criterion.
StretchS9 · A tokenizer on a rate–distortion curve

Train BPE at several vocabulary sizes and plot bits per character against the vocabulary's own description cost. Find the interior optimum of the total.

Answer. Larger vocabularies shorten sequences and cost more to specify, so the total has a minimum, which is why the right vocabulary size is an interior optimum rather than as large as you can afford. This is Part XX §1–§8's choice restated in bits, and the restatement is what makes it a calculation.
StretchS10 · A scaling law is a compression curve

Take a loss-against-compute fit in nats per token, convert to bits, and express it as bits of the corpus bought per unit of computation. Interpret the irreducible term.

Answer. Cross-entropy is a code length, so the curve says how many bits of the corpus a given amount of computation buys. The irreducible term is the corpus's own entropy (the part no model compresses because there is nothing there to compress), which is why fits that omit it extrapolate to impossible losses.
StretchS11 · Compress the training set verbatim

Build a "model" that memorises the training set exactly, and compute its two-part description length honestly. Compare against a fitted polynomial.

Answer. Zero residual bits and an enormous model cost, so the total is far worse. This is the sanity check behind every claim of the form "system A compresses the data better than system B": ask what was billed and to whom, because a compression ratio quoted without its decompressor is not a measurement.
