The architecture

How the book is built, why it is ordered this way, and what each part is for. Read this once; return to it whenever you want to know where you are.

§ The spine

Everything rests on a single claim: an intelligent system is a function with adjustable parameters, and learning is adjusting them to reduce a measured error. That sentence contains the whole book. Unpacking it honestly is what takes the pages.

whatA function, so we need functions, composition, and how to differentiate them. Part 0.
on whatActing on vectors and matrices, so we need linear algebra. Part I.
under whatUnder uncertainty, producing distributions rather than answers, so we need probability, and information theory to measure the gap between distributions. Part II.
howComputed in finite precision on real hardware, so we need numerical methods. Part III.
with whatExpressed through a framework that records what your code did, so we need to read one. Part IV.
why it worksGeneralising to data never seen, so we need the theory of learning. Part V.
the systemsAnd then the architectures themselves: networks, regularization, optimization, convolution, sequences, attention, representation, generation, scale. Parts VI onward.

§ Where each part goes

Each part is built toward one destination. Knowing the destination makes the route legible.

PartEnds atWhy that is the destination
0
Mathematics		 One backpropagation step, by hand Every symbol in a training loop, computed with real numbers on paper. Once you have done it once, everything after is scale.
I
Linear algebra		 Principal components, derived from nothing The first genuine learning algorithm, and it turns out to be an eigendecomposition asked the right question.
II
Probability		 Cross-entropy, from maximum likelihood The objective nearly every model is trained on, shown to be not a convention but a consequence.
III
Numerical computation		 Least squares, three ways, one of which fails Three algorithms, identical in exact arithmetic. In floating point one collapses where the others are comfortable. Algebraic equivalence is not numerical equivalence.
IV
The framework		 A training run you can debug rather than restart Placed here because every line of a training loop has now been derived. Nothing in it is a magic word.
V
Statistics		 The bias–variance decomposition, and where it breaks The identity that organises every later technique, followed by the honest account of why the classical U-curve does not describe modern networks.
VI
Machine learning		 The manifold hypothesis Why the classical methods hit a wall, and why composition rather than smoothness is the prior that gets past it. The argument for depth, made before any network.
VII
Neural networks		 An automatic differentiation engine, in twenty lines The point at which a framework stops being a black box, because you have written the part that seemed like magic.
VIII
Regularization		 Six techniques shown to be the same technique Input noise is weight decay; early stopping traverses the same family. The measurements are in the part, not the footnotes.
IX
Optimization		 A diagnostic ladder for a run that will not train Six measurements that cost almost nothing and between them eliminate most of the folklore, starting with the one that proves you are nowhere near a local minimum.
X
Convolutional models		 An assumption about space, priced exactly One symmetry, encoded so firmly the model cannot consider anything else, and every property of the architecture follows from it, including all four of its limits.
XI
Sequence models		 An unsolved problem, stated precisely Sharing across time buys any length and costs a path between distant positions that grows with the sequence. The part ends on the four things it could not do, because the next one is organised around removing them.
XII
Attention		 A capability nobody designed Removing the bottleneck bought a constant path length and cost an unbounded state, and produced, unasked, a model that learns a task from examples in its prompt with no weight changing.
XIII
Data		 What a dataset commits you to Scale improves precision and does nothing for validity. Every other decision in this book is revisable by spending compute; the frame you sampled from is not.
XIV
Practice		 Diagnose before treating Every remedy in this book treats one condition and makes another worse. The instruments that tell you which condition you have cost minutes; the habit of reaching for them before reaching for a fix is the part.
XV
Representation		 The objective decides what is kept A representation is the exact solution of the problem posed. Every surprise in the part came from the problem being subtly different from the one intended, which is a question you can answer on paper, before spending the compute.
XVI
Generative		 One question, five answers Every generative model is a different thing to do about the normalising constant. Score-based methods won because they did not relocate the difficulty; they differentiated it away.
XVII
Scale		 Arithmetic before anything else Memory, communication, the pipeline bubble and the compute-optimal split are all counting, done before any hardware is requested. And an empirical law inherits every choice made in the runs behind it.
XVIII
Reinforcement		 You caused your own data The agent optimises the reward you wrote using data it chose to collect. Both halves cause the difficulties, and every method in the part answers one of them.
XIX
Efficiency		 Bandwidth, not arithmetic Generation is limited by memory bandwidth, so quantization works, unstructured sparsity does not, and batching is the largest lever. Measure time, not FLOPs.
XX
Language		 One objective, everything else downstream Next-token prediction on enough text produced instruction-following, in-context learning and reasoning as side effects. The tokenizer is chosen first and constrains everything after; evaluation is the part we are worst at.
XXI
Alignment		 Present is not used, and absent is not measured A probe finds what a representation holds; only an intervention finds what the network uses. A clean evaluation bounds a failure rate far more weakly than it feels like. Both gaps are arithmetic, and both are where confident claims go wrong.
XXII
Causality		 Prediction is not intervention What goes with what does not tell you what changes what, and the gap is bias rather than variance; it does not shrink with data and no diagnostic in Part XIV can see it. Which variables to control for is a claim you defend, not one you fit.
XXIII
Theory		 The guarantee ran out; the algorithm took over Finite capacity is exactly what makes learning possible, and modern models have none; they fit random labels, so no distribution-free bound over them says anything. What is left is that the optimiser chooses among the perfect fits, and chooses well.
XXIV
Uncertainty		 An interval makes a promise you can check Nominal coverage is a claim, and measuring it separates the methods that keep it from the ones that do not. A guarantee is available for any model at the cost of a calibration set, and it holds exactly until the data stops resembling that set, then fails silently.
XXV
Tabular		 The family is a prior about the function's shape Trees represent thresholds exactly and hyperplanes as staircases; networks are the reverse. Neither wins on "tabular data"; the generating process decides. And if the rows are ordered, a random split reports a model that does not exist.
XXVI
Graphs		 An architecture is a declaration about symmetry A graph has no node ordering and a molecule has no orientation, so a model reading either should be built not to notice. Building the symmetry in is exact where learning it is approximate, and the standard way of doing it has one limit that is provable and two that are structural.
XXVII
Signals		 A symmetry picks a basis, and the basis decides what is easy Convolution is multiplication in frequency, which is the theorem Part X rests on. Every stride is a resampling, and resampling without filtering relabels information rather than losing it. And gradient descent learns low frequencies first, which is most of what this book has been calling implicit regularisation.
XXVIII
Inference		 Write the model as a distribution and fitting becomes inference A graph is a factorisation, and its treewidth decides whether the posterior is computable at all. When it is not, you choose between an approximation whose error does not shrink with compute and a sampler that cannot tell you when it has arrived. That choice usually decides whether the system works.
XXIX
Vision		 Some errors are the measurement, not the model Every structured output needs a matching rule and a metric with a threshold in it, and the threshold changes which system is better. But a single view has no scale, a local window has no motion along an edge, and stereo depth error grows with the square of range, none of which a larger network touches.
XXX
Audio		 Choose the representation with the care you give the model A spectrogram is a guess about how fast the signal changes, a claim that resolution should degrade like hearing's, and the deletion of the half that carries the structure. The cheapest way to align audio to text assumes the output symbols are independent, which costs half the probability mass whenever the audio is ambiguous.
XXXI
Control		 The policy determines the data, so building it is the smaller half Feedback substitutes for knowledge, so the model matters less than the loop it sits in. A learned model's usable horizon is set by the plant's stability, not the model's accuracy. And a million failure-free miles bounds a failure rate only below one in three hundred thousand.
XXXII
Systems		 The currency is bytes moved, and the adversary changes the question A machine does a hundred arithmetic operations in the time of one fetch, so the two transformations that make code fast change no arithmetic at all. And once someone is trying to make your system fail, what protects it is the architecture around the model rather than any property of the model.
XXXIII
Search		 Computation spent at the moment of use, and what decides whether it helps A heuristic buys far less than advertised and buys it only when nearly exact; move ordering is worth a doubling of search depth. And sampling more candidates raises the accuracy a verifier must have to be worth consulting, because a maximum over more draws finds the tail.

§ Dependencies

The order is close to strictly sequential, which is deliberate. A few specifics worth knowing:

  • Part 0 is required for everything. Nothing later works without the chain rule and logarithms.
  • Part II leans on Part I only lightly (in one section, and that section says so). If Part I bruises you, Part II is a genuine chance to rebuild momentum.
  • Parts I and II converge in Part II §13, where the covariance matrix turns out to be exactly the symmetric positive-semidefinite object the spectral theorem was built for. That convergence is why PCA exists, and it is the first place the foundations visibly combine.

§ Three routes

Building from nothing
Everything in order, every Try it, Tier 1 and Tier 2 drills in each part. Several weeks at a relaxed pace. This is the intended path and the one the book is optimised for.
Refreshing
Skim Part 0 but take its checkpoint; slow down at logarithms and the chain rule; read Parts I and II properly. About two weeks.
Reference
Use the glossary and this map. Every section is self-contained enough to read alone, and cross-references are explicit rather than implied.

§ Code, and the two kinds of it

This book builds things from nothing. Every algorithm is implemented with NumPy and arithmetic, because a method you have written once is a method you can reason about, debug, and modify; one you have only called is not.

But nobody works that way in practice, and a book that left you unable to read ordinary model code would have failed at its actual job. So there are two kinds of code here, and they are visually distinct:

plainNumPy, in the body text. The idea implemented from scratch, so you can see there is nothing hidden.
boxedPyTorch, in an In the framework box. The same idea as practitioners actually write it: with what the library is doing, why it is designed that way, and what breaks.

The framework boxes are not a reference card. Each one appears only after the thing it describes has been derived, and each explains the correspondence rather than assuming it: what the arguments mean in terms of the mathematics you just did, which numerical decision the function name is hiding, and what the characteristic failure looks like. Where a verified snippet reproduces a number computed earlier by hand, it says so: the first of them, in Part 0 §24, exists precisely to prove that the hand computation was the real thing.

PyTorch is used throughout because it is dominant in research and its API sits closest to the notation. TensorFlow and Keras equivalents are given where they differ in a way that would actually catch you out (a transposed weight, an unsafe default) rather than routinely.

On the parts still being written

Thirty-four parts are written: mathematical foundations, linear algebra, probability and information theory, numerical computation, the framework, statistics and estimation, machine learning basics, neural networks, regularization, optimization, convolutional models, sequence models, attention and transformers, data, practice and diagnosis, representation learning, generative models, scale, reinforcement learning, efficiency and deployment, language models, alignment, interpretability and consequence, causal inference, learning theory, uncertainty quantification, structured and tabular learning, graph and geometric learning, signals and spectra, probabilistic models and inference, perception in two modalities, control, systems and security, and search and planning.

The structure is designed so that arrival costs nothing. A new part is a set of sections, its figures, its drills and its glossary entries. Nothing already written needs to change, and no cross-reference breaks.
