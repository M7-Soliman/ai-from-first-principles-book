BuildThe project

Ten to fourteen hours. You solve a small MDP exactly, then rebuild the same answer four ways from samples, and use the exact solution to catch each method failing in its own characteristic way.

P.1 What you are building

rlbench: an exact solver, four sampled learners, and the instruments that show what each one gets wrong.

The rule: solve it exactly first. Every claim in this project is checked against a number you computed rather than against a learning curve going up, and that is the whole reason the project uses a small MDP rather than a game.

P.2 Stage 1: the exact solver

  1. A random MDP generator, and a gridworld with a goal.
  2. Value iteration, policy iteration, and exact policy evaluation by linear solve.
  3. Verify all three agree, and that value iteration reaches the same fixed point from wildly different starting values.
  4. Measure the per-sweep contraction rate and compare it to $\gamma$.

Deliverable: $V^*$, the optimal policy, and the measured contraction rate against theory. Everything downstream compares to these.

P.3 Stage 2: learning values from samples

  1. TD(0) and Monte Carlo evaluation, both against the exact $V^\pi$.
  2. Sweep the episode budget and report error and spread across at least ten seeds.
  3. Implement $n$-step returns and sweep $n$.
  4. Then decay the step size and show that the plateau both methods hit was the step size, not the method.

Deliverable: the error-against-budget curves with spreads, and the best $n$. Predict the shape of the $n$ sweep before you run it.

P.4 Stage 3: control, and two failures

  1. SARSA and Q-learning on the cliff gridworld. Compare the paths learned against the rewards actually collected.
  2. Build the two-state MDP that exposes the maximisation bias. Run Q-learning and double Q-learning, and report how often each takes the action that is genuinely worse.
  3. Implement Baird's counterexample. Run all four conditions and plot $\|\mathbf{w}\|$.
  4. Add a target network to the diverging case and sweep the update interval.

Deliverable: three plots and one sentence each on the mechanism. For Baird's, be careful that "on-policy" means the state distribution too, getting that wrong makes it look as though the counterexample always diverges.

P.5 Stage 4: policy gradients

  1. A one-step problem where the exact gradient is computable. Measure the sampled estimator's bias and variance with and without a baseline.
  2. Shift every reward by $+100$ and repeat. Explain the result.
  3. REINFORCE on the gridworld, then with a baseline, then actor–critic with GAE.
  4. Add PPO's clipping and plot the objective against the ratio for both signs of advantage.

Deliverable: the bias-and-variance table, and learning curves over ten seeds for the four variants. Step two is the one that makes the baseline's mechanism obvious.

P.6 Stage 5: exploration

  1. Four bandit strategies, run to a long horizon. Report cumulative regret and the per-step regret over the final quarter.
  2. Then the chain task: reward behind a specific $n$-step sequence. Increase $n$ until $\epsilon$-greedy stops finding it, and record the $n$.
  3. Add a count-based bonus and find how much further it gets.

Deliverable: the regret slopes, and the $n$ at which undirected exploration fails. That second number is the honest scale of the exploration problem.

P.7 Stage 6: reward design

  1. Add potential-based shaping with a large arbitrary potential. Confirm the optimal policy is unchanged by comparing achieved values, and that $V$ shifts by exactly $-\Phi$.
  2. Add an arbitrary action-dependent bonus and confirm the optimal policy does change.
  3. Build a proxy reward that a cycle exploits. Solve exactly for both objectives and report each policy's return under each.
  4. Plot the proxy reward over training for the hacking policy.

Deliverable: the two-by-two return table, and the reward curve from step four, which rises the whole time while the agent does the wrong thing.

P.8 Stretch

  • Offline. Log data from a mediocre policy, run Q-learning on it with no interaction, and watch the values grow without bound. Then constrain to the data and watch it stop.
  • A reward model, over-optimised. Generate preferences from a known utility, fit a model, optimise against it, and plot model score against true utility.
  • Seeds. Thirty runs of one algorithm; report the full distribution and what three seeds would have said.
  • Imitation first. Behaviour cloning against RL at matched compute.
  • The noisy TV. A curiosity bonus and an unpredictable stimulus.

P.9 Done when

  • Three exact methods agree, and the contraction rate matches $\gamma$.
  • Every sampled result is reported against the exact answer, with a spread over seeds.
  • You have measured the maximisation bias and shown double estimation removing it.
  • Baird's counterexample diverges, and each of the three removals fixes it.
  • You have the bias-and-variance table for the policy gradient, before and after the reward shift.
  • You know the $n$ at which $\epsilon$-greedy stops finding the reward.
  • You have confirmed potential-based shaping is safe and an arbitrary bonus is not.
  • You have a policy that maximises its reward and does the wrong thing.
  • Your README names one result that changed when you increased the number of seeds.
Why this project

Stage 1 is the reason for the ordering. Almost every published reinforcement learning result is a curve going up, and a curve going up is compatible with a great many things being wrong. Solving the problem exactly first converts every later claim from "it improved" into "it reached the right answer, or it did not".

Stage 3 is the second reason. Three of the most-cited failures in the subject (the cliff, the maximisation bias, Baird's counterexample) are each about ten lines, and each is far more convincing constructed than described.

The one thing to carry forward

The agent optimises the reward you wrote, using data it chose to collect.

Both halves cause the difficulties. Because the reward is what is optimised, any gap between it and your intention gets found. Because the data is chosen by the policy, an early mistake removes the evidence that would have corrected it, a bad step is not recoverable, and the training distribution moves as the learner moves.

Every method here answers one of those. And the practical summary that most often matters: if you can turn the problem into supervised learning, do. The cases where this part is necessary are fewer than the number of projects that reach for it.
