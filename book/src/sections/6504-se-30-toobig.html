Part CToo big to hold

A* keeps the frontier in memory, and on any interesting problem the frontier is the problem. This movement is the set of things people do instead: keep only the best few, keep only the current one, keep none and re-derive, or keep a bound and use it to throw away whole regions unexamined. Each gives up something, and it is worth being precise about which thing.

§15 Local search

Forget the path

Local search holds a single complete candidate and repeatedly moves to a neighbour. There is no frontier, no closed list, and no path: memory is $O(1)$ in the size of the space. It applies whenever the goal is a state rather than a route to one: a schedule, a layout, a set of weights.

Hill climbing moves to the best neighbour and stops when none is better. It is gradient ascent for problems with no gradient, and it fails the same way: local optima, plateaus where every neighbour is equal and there is no signal about which way to go, and ridges that require moving two axes at once when only single-axis moves are available.

The failure modes matter more than the algorithm because they name things you will meet elsewhere. A plateau is what a flat loss landscape looks like without a derivative to tell you it is flat. A ridge is what an ill-conditioned optimum looks like to a method with axis-aligned steps, the same pathology Part IX §14 fixed with momentum and preconditioning. Local search is where those shapes were first named.

§16 Getting out

Three escapes, in increasing order of principle

Random restarts. Run hill climbing from many starts and keep the best. Embarrassingly parallel, and if the probability of a start reaching the global optimum is $p$, the expected number of restarts is $1/p$. Unreasonably effective, and the first thing to try.

Simulated annealing. Accept a worsening move of size $\Delta$ with probability $e^{-\Delta/T}$, and lower $T$ over time. At high $T$ it wanders, at low $T$ it is hill climbing, and with a slow enough schedule it converges to the global optimum, a guarantee whose required schedule is too slow to use, which is honest to admit. Note the form of the acceptance rule: it is Metropolis–Hastings from Part XXVIII with the temperature falling, and the connection is not a coincidence.

Tabu search. Keep a short memory of recently visited states and forbid returning to them, which forces the search out of a basin it would otherwise cycle in. Cheap, unprincipled, and often the best of the three on structured combinatorial problems.

§17 Beam search

Breadth-first with a budget

Keep the $k$ best partial solutions at each depth, expand all of them, score all the successors, keep the best $k$ again. Memory is $O(k)$ and time is $O(kbd)$, both linear in the depth, which is the whole point.

It is incomplete and suboptimal, and it is what almost every sequence model uses at generation time, so its failure modes are worth more attention than its guarantees.

§18 What beam search is actually doing

Go and read

Meister, Vieira & Cotterell (2020), If beam search is the answer, what was the question?. Takes the observation behind Figure 4 seriously: a narrow beam is not an approximation that happens to work, it is an implicit regulariser, and the paper identifies what it regularises toward. The honest treatment of a result usually passed on as folklore.

Search error is not always error

The standard mental model (the beam is an approximation and a wider beam is a better one) is wrong in a specific and useful way. The beam is approximating the model's optimum, and the model is an approximation of what you want. When the second approximation is the worse of the two, tightening the first makes the composition worse.

This is the honest version of the folklore that beam search regularises. It is not that a narrow beam is secretly wise; it is that a narrow beam is biased toward high-probability-per-step sequences and away from the exotic ones a mismatched objective rewards. The bias happens to point in a useful direction. That is luck, and it stops being lucky the moment the model improves.

Two consequences worth carrying. Never tune a beam width on a proxy metric and expect the result to hold when the model changes: Figure 4's curves are qualitatively different at the two correlations. And if widening the beam degrades your metric, that is not a search bug, it is a measurement: your objective disagrees with your metric, and you have just found out by how much. The same diagnostic applies to reward models in Part XXI, and to the verifier in §41.

§19 Branch and bound

Prove a region is worthless without looking inside it

Search the tree depth-first, keeping the best complete solution found so far, the incumbent. At each node compute a bound on the best solution achievable in its subtree. If the bound is no better than the incumbent, discard the entire subtree unexamined.

The result is exact: it returns the true optimum, and it returns a proof, because at termination every region has either been searched or bounded away. What varies is how much of the tree survives, and that is entirely a property of the bound.

§20 Where bounds come from

The same idea as §13, doing more work

A bound is a relaxation solved exactly, which is the identical construction as an admissible heuristic, and branch and bound is A* rearranged to use memory like depth-first search. Drop the integrality constraint from an integer program and you get a linear program, solvable in polynomial time, whose optimum bounds the integer optimum. Drop a coupling constraint and the problem separates. Drop precedence and you get a sum of independent pieces.

Figure 5 says something sharper than "a good bound is better". Both bounds are valid, so both algorithms are correct and return the same answer. But one of them is a usable algorithm at $n=30$ and the other is not an algorithm at all. Validity is a correctness property and tightness is the entire performance story, and it is the tightness nobody puts in the paper's theorem.

§21 Trading time for memory

Go and read

Korf (1985), Depth-first iterative-deepening: an optimal admissible tree search. IDA*, and the analysis of why re-expanding everything each round costs so little. The argument that memory rather than time is the binding constraint is made here more clearly than anywhere since.

When the frontier will not fit

IDA*. Iterative deepening with an $f$-cost limit rather than a depth limit: run a depth-first search that prunes anything with $f \gt \text{limit}$, and if it fails, raise the limit to the smallest $f$ that was pruned. Memory $O(d)$, optimal with an admissible heuristic, and it re-expands everything each round. It is how the 15-puzzle was first solved optimally, and it is the right answer whenever nodes are cheap to regenerate and expensive to store.

Memory-bounded A*. Run A* until memory is full, then drop the worst frontier node and record its $f$ value in its parent, so the region can be regenerated if everything else turns out worse. Optimal if the optimal solution fits in the memory you have, which is the sort of guarantee that sounds weak and is exactly what you want.

Bidirectional search. Search forward from the start and backward from the goal until the frontiers meet: $2b^{d/2}$ instead of $b^{d}$. The same square-root saving §36 gets from move ordering, and far harder to implement correctly, because detecting the meeting and proving the meeting point optimal are both fiddly and the backward successors may not be computable at all.

§22 Choosing to stop being optimal

A decision to make explicitly, once

This movement is a sequence of surrenders and it is worth writing down what each one costs, in the order you should consider them.

Keep optimality, lose memory guarantees: A* with a good heuristic. Keep optimality, pay time for memory: IDA*, branch and bound. Keep a bound on suboptimality: weighted A* at 1.25× when the guarantee said 8×. Keep nothing but an answer: beam search, local search, sampling.

Most systems land in the last category by accident rather than decision, usually because the first thing anyone implements is sampling and it works well enough. The reason to know the ladder is that when it stops working well enough, "sample more" is the worst of the available moves and the one everybody reaches for. §41 measures why.
