Part DWhat fixes it

Every remedy in this part is the same idea at a different level of sophistication: build a path through time along which the product of derivatives is near one. Skip connections do it with an integer, leaky units with a fixed real number, and gated units with a number the network computes for itself at every step.

§16 Skip connections through time

An ordinary recurrent connection runs from step $t$ to step $t+1$. Add connections that span $d$ steps and a gradient can travel back along the long edges, encountering $\tau/d$ factors rather than $\tau$.

The decay is therefore exponential in $\tau/d$ rather than in $\tau$, which is a real improvement and a limited one. The short connections are still there, so explosion is still exponential in $\tau$: you have improved the vanishing without touching the explosion, and you have added a hyperparameter, $d$, that fixes the reachable time scale in advance.

§17 Leaky units

Replace the integer $d$ with a real number and the same idea becomes smooth and adjustable. Give a unit a linear self-connection with weight near one:

$$\mu^{(t)} = \alpha\,\mu^{(t-1)} + (1-\alpha)\,v^{(t)}$$

which is a running average: the same exponentially decaying accumulator that appeared as momentum's velocity (Part III §15), RMSProp's gradient accumulator (Part III §16), batch normalisation's running statistics (Part IX §23), and Polyak averaging (Part IX §25). This is now its fifth appearance. The derivative along the self-connection is exactly $\alpha$ per step, so the path from $\mu^{(0)}$ to $\mu^{(t)}$ contributes $\alpha^t$, and choosing $\alpha$ near one makes that as close to unity as you like.

Why $1/(1-\alpha)$ keeps appearing

The same update rule ($x \leftarrow \rho x + (1-\rho)u$) has now appeared five times: momentum's velocity (Part III §15), RMSProp's gradient accumulator (Part III §16), batch normalisation's running statistics (Part IX §23), Polyak averaging (Part IX §25), and now a hidden unit's memory. In every case it sums a geometric series with ratio $\rho$, weighting the last $1/(1-\rho)$ inputs appreciably and almost nothing before that.

Registering it as one mechanism with five uses rather than five coincidences is worth more than any of the individual facts.

Two ways to set the time constants. Fix them, sample once at initialisation and leave them, which gives you a network with a spectrum of time scales, some units watching the last two steps and some the last hundred. Or make them parameters and learn them. Both help; having a range of scales appears to matter more than getting any one of them right.

A third variant is worth naming because it does something the others do not. Rather than adding long connections, remove the short ones from some units, forcing them to operate on a long time scale. A skip connection lets a unit attend to the distant past; a removed short connection makes it. Groups of units updated at different frequencies is the same idea made discrete.

§18 The LSTM

In 60 seconds

A leaky unit's $\alpha$ is fixed. Sometimes you want to remember for a hundred steps and then, on seeing a particular input, forget everything and start again. Make $\alpha$ a function of the input (computed by the network, at every step, per unit), and you have an LSTM. Everything else is bookkeeping around that one change.

Go and read

Hochreiter & Schmidhuber (1997), Long short-term memory. Long, and worth it for the framing: the paper is written as an error-flow analysis first and an architecture second, so the cell is derived from what the gradient needs rather than proposed and justified. Note that the original has no forget gate: it was added three years later by Gers, Schmidhuber & Cummins (2000), which is also where the bias-of-1 advice of §20 comes from.

Leaky units accumulate. What they cannot do is clear. If a sequence is made of sub-sequences and a unit should gather evidence within each one, something must reset it at the boundary, and you would rather the network learned when to do that than fixed it in advance.

The LSTM cell

A forget gate, which is the leaky unit's $\alpha$ made conditional:

$$f^{(t)} = \sigma\Big(b^f + U^f\mathbf{x}^{(t)} + W^f\mathbf{h}^{(t-1)}\Big)$$

An input gate $g^{(t)}$, with the same form, deciding what is allowed into the cell:

$$g^{(t)} = \sigma\Big(b^g + U^g\mathbf{x}^{(t)} + W^g\mathbf{h}^{(t-1)}\Big)$$

The cell state updates with a self-loop whose weight is $f^{(t)}$, the leaky unit's $\alpha$, now computed by the network at every step:

$$s^{(t)} = f^{(t)} s^{(t-1)} + g^{(t)}\,\tanh\Big(b + U\mathbf{x}^{(t)} + W\mathbf{h}^{(t-1)}\Big)$$

The cell candidate uses $\tanh$ rather than $\sigma$ so that the cell can hold both positive and negative values; a sigmoid candidate would push the cell state positive only. An output gate $q^{(t)}$ decides what the rest of the network gets to see:

$$q^{(t)} = \sigma\Big(b^q + U^q\mathbf{x}^{(t)} + W^q\mathbf{h}^{(t-1)}\Big) \qquad h^{(t)} = \tanh\big(s^{(t)}\big)\, q^{(t)}$$

All three gates are sigmoids, so they lie in $(0,1)$ and act as soft switches. The $\tanh$ in $h^{(t)}$ squashes the accumulated cell magnitude back into $(-1,1)$ before the output gate multiplies it: it is not a gate, it is a nonlinearity that keeps the hidden state bounded.

This section names the input gate $g^{(t)}$, following Goodfellow's notation; §21's framework box and the drills instead follow PyTorch's convention, where $g$ denotes the $\tanh$ cell candidate above and the input gate is $i$, same two objects, the letters swapped between sources.
Intuition: the whole design in one line

Compare the cell update with §17's leaky unit:

$$\mu^{(t)} = \alpha\,\mu^{(t-1)} + (1-\alpha)v^{(t)} \qquad\text{against}\qquad s^{(t)} = f^{(t)} s^{(t-1)} + g^{(t)} v^{(t)}$$

They are the same equation. The differences are that $\alpha$ has become $f^{(t)}$, which the network computes rather than you, and that the two coefficients are now independent, so the cell can retain and absorb, or retain and ignore, rather than trading one against the other.

That is the entire idea. The time constant of integration is an output of the model, so a network with fixed parameters can integrate over two steps in one context and two hundred in another, decided by what it is reading.

The gradient consequence is immediate. Along the cell's self-loop the derivative is $\prod_t f^{(t)}$ rather than a product of Jacobians, a product of numbers the network chooses, which it can keep near one for as long as it needs to. §11's exponential decay is not defeated so much as put under the model's control.

§19 What the gates actually do

The equations say what the gates are. Training one and reading them says what they do.

Two readings worth separating. The forget gate near 0.9 is the mechanism working exactly as designed: the network has discovered that this task needs a long time constant and set one. The factor-of-forty growth in the cell magnitude is the input gate continuing to admit the noise that follows the signal: the cell integrates everything it is given, and what makes the task solvable is that the signal survives alongside, not that the noise is excluded.

§20 The forget-gate bias

Figure 5 showed the gated architectures doing worse than a vanilla RNN at long lags, which is not what anyone expects. Here is why, and it is a one-line fix that most treatments omit.

Why the default handicaps the architecture that was built to fix this

A bias of zero puts the forget gate at $\sigma(0) = 0.5$ at initialisation. So an untrained LSTM halves its cell state at every step, a memory horizon of about one step, and the gradient along the self-loop decaying as $0.5^t$, which is precisely the vanishing the cell exists to prevent.

The network can learn to open the gate. But it has to learn it through a gradient that the closed gate is busy destroying, which is a chicken-and-egg problem, and on a long task it frequently does not get there in the budget available.

Initialising the bias to 1 puts the gate at $\sigma(1) = 0.73$; to 2, at 0.88. The cell starts in a retaining regime, the gradient reaches back far enough to learn from, and the network can adjust from there.

This is Part IX §17's gate-bias rule ("set the bias so the gate starts open, or the thing it controls never gets a chance to learn"), and Figure 8 is that rule costing well over twenty points of accuracy when ignored, on this run. It is also, on the evidence of §14, large enough to reverse the headline comparison between architectures.

§21 GRU, and the honest comparison

Go and read

Greff et al. (2017), LSTM: a search space odyssey. Eight LSTM variants, thousands of runs, and a clear answer: none of them reliably beats the standard cell, and the forget gate is the component that matters. Read it beside Jozefowicz, Zaremba & Sutskever (2015), which searched over ten thousand architectures and found that adding a bias of 1 to the forget gate makes the plain LSTM as strong as anything the search produced. Two large studies whose main finding is that an initialisation was doing the work.

Which parts of the LSTM are necessary? The gated recurrent unit is the most successful attempt to find out, and it removes one gate by merging two decisions.

The gated recurrent unit

Two gates, each a sigmoid: an update gate $u^{(t)}$ (controlling what is kept versus replaced) and a reset gate $r^{(t)}$ (controlling how much of the previous state enters the candidate):

$$u^{(t)} = \sigma\!\Big(b^u + U^u\mathbf{x}^{(t)} + W^u\mathbf{h}^{(t-1)}\Big) \qquad r^{(t)} = \sigma\!\Big(b^r + U^r\mathbf{x}^{(t)} + W^r\mathbf{h}^{(t-1)}\Big)$$

The update is then:

$$h^{(t)} = u^{(t)} h^{(t-1)} + \big(1 - u^{(t)}\big)\,\tanh\Big(b + U\mathbf{x}^{(t)} + W\big(\mathbf{r}^{(t)}\odot\mathbf{h}^{(t-1)}\big)\Big)$$

There is no separate cell state and no output gate: the state is exposed directly, and the two coefficients $u^{(t)}$ and $1-u^{(t)}$ sum to one, so the GRU's forgetting and admission are one decision rather than two independent ones. Fewer parameters, fewer operations, and (in most comparisons) the same accuracy.

Why there is no winner, and what that tells you

Many variants have been proposed and systematically compared. The findings are consistent and worth stating plainly:

  • No variant clearly beats both LSTM and GRU across a range of tasks.
  • The forget gate is the crucial ingredient: remove it and performance collapses; the others matter much less.
  • Adding a bias of 1 to the forget gate makes the plain LSTM as strong as the best variant found by search.

Read those three together and the conclusion is uncomfortable and correct: the architecture search largely rediscovered an initialisation. Figure 8 is that result at a scale you can reproduce in an afternoon, and it is Part IX §18's answer about optimisers arriving in a different literature: the returns to understanding one mechanism well exceed the returns to picking the right variant.

In the framework, and the default you now have a reason to override

Having derived the cell, the mapping is direct. What matters is the argument that is not there.

import torch.nn as nn

rnn  = nn.RNN(64, 128, batch_first=True, nonlinearity="tanh")
lstm = nn.LSTM(64, 128, num_layers=2, batch_first=True)   # section 23
gru  = nn.GRU(64, 128, batch_first=True, bidirectional=True)  # section 22

output, (h_n, c_n) = lstm(x)      # output: every step. h_n: the last one.

# section 20: there is no forget_bias argument, so do it yourself
for name, p in lstm.named_parameters():
    if "bias" in name:
        n = p.shape[0] // 4
        with torch.no_grad():
            p[n:2*n].fill_(1.0)     # gate order is i, f, g, o

What each piece corresponds to. output holds $\mathbf{h}^{(t)}$ for every step: use it when there is a loss at each step. h_n is the final state only: use it as §27's context. c_n is the cell state $s^{(t)}$, which is a separate thing from $h$ and exists only for the LSTM.

Why the slicing is what it is. All four gates' parameters are stored in one concatenated tensor, in the order input, forget, cell, output, so the forget gate's bias is the second quarter. There are two bias vectors, bias_ih and bias_hh, which are added together; setting one to 1 gives an effective bias near 1, and setting both gives 2.

What breaks. Three things.

No forget_bias argument exists. TensorFlow's LSTM has had one, defaulting to 1, for years; PyTorch does not, and its default is 0. Figure 8 measures what that costs. This is the single most valuable line in this box.

batch_first defaults to False, meaning the expected shape is $(T, N, C)$ rather than $(N, T, C)$. A batch of 32 sequences of length 100 fed the wrong way round becomes 100 sequences of length 32, which is a valid tensor of the wrong thing and does not raise (Part X §6's channels-first trap, in a new axis).

Variable-length batches need packing. Padding a batch to its longest member and running it directly means the recurrence consumes the padding, and the final state is the state after reading zeros. pack_padded_sequence exists so the recurrence stops at each sequence's true end. Forgetting it degrades a model quietly and in proportion to how variable your lengths are.
